TL;DR — This PR brings ~18 months of upstream 3.x maintenance (Jan 2025 → Aug 2026) into the fork. The engine-facing changes are mostly additive and backward-compatible for GDScript — no GDScript API was removed. The real risk is concentrated at the C++ / build-system level: the bump to C++17, a deep refactor of the core containers (LocalVector/PoolVector/Vector/Span), and the switch from dynamic_cast to Godot's built-in casting. Those affect the fork's own C++ code — the GodotSteam module and the custom navigation changes — and must be verified with a clean compile, not just a merge.

1. Executive summary

The PR merges godotengine/godot 3.x into the fork's 3.x-fannypack branch. The fork last synced with upstream around commit 5e904cd4 (2025-01-22); the fork's branch then diverged with 37 commits of its own (GodotSteam, navigation, CI). This PR replays the 260 upstream commits accumulated since.

Two forces dominate the diff:

  • Volume is dominated by third-party updates. The mbedTLS upgrade (2.28 → 3.6.7) and libpng (1.6.58) account for ~90 K lines of the 129 K insertions. These are dependency bumps, mostly invisible to game code.
  • Semantic change is dominated by the Physics Interpolation rework. Over 50 of the 260 commits belong to the "FTI" (fixed-timestep interpolation) effort, culminating in moving 3D interpolation from VisualServer into SceneTree. The user-facing API is preserved, but the implementation is essentially rewritten.

Bottom line: for a GDScript-only game, this update is low-risk and mostly beneficial (bug fixes, performance, security). The meaningful work is making sure the fork's custom C++ code compiles and behaves correctly against the new core — this is where the only real breaking changes live.

2. Scope & methodology

The analysis was done directly against the local repository:

  • Merge base (common ancestor of both branches): 5e904cd4 (upstream PR #100389, 2025-01-22).
  • Base 3.x-fannypack = 6bd8e11f (2025-02-17, "Fix crash del editor al seleccionar nodos").
  • Head 3.x = e1e12161 (2026-08-18, upstream PR #122508).

Upstream changes were enumerated with git rev-list / git diff between the merge base and head, then classified by commit message and by files touched. The fork's own 37 commits were diffed separately to locate conflict and compile risks.

4. Breaking changes — what to worry about

Ordered by how likely each is to bite this fork. Nothing here breaks GDScript projects. Every item is a C++/build/dependency/behavioral concern.

SeverityAreaChange & impactAction for the fork
CRITICAL Build system C++17 is now required and enforced. SConstruct hard-fails on GCC < 9, Clang < 6, Apple Clang < 10, and MSVC < 2017 15.9. The fork's CI (GitHub Actions workflows) and any local toolchains must satisfy this or builds will abort at configure time. Verify CI build images and local compilers meet the minimums. This is a hard gate, not a warning.
HIGH Core containers (C++) PoolVector is now a wrapper over LocalVector; implicit LocalVector→Vector and LocalVector→PoolVector conversions were removed, replaced by an explicit Vector(Span) constructor and explicit Span conversions. Move semantics were added; [[lifetimebound]] was introduced. Any C++ module relying on the old implicit conversions will fail to compile. Compile the fork's C++ modules against the new headers. GodotSteam only declares PoolVector<uint64_t> directly (low risk), but this must be confirmed.
HIGH Object casting (C++) dynamic_cast was replaced by Godot's in-built cast_to on all platforms; ObjectDB::get_instance() is now templated (nominally backward compatible); Object::derives_from / is_reference / ancestry were optimized. C++ code using dynamic_cast or the old get_instance signature is affected. Audit custom C++ for dynamic_cast and ObjectDB::get_instance usage. None found in the fork's nav/CSG/triangle edits.
HIGH Scene-tree internals (C++) Node, Spatial and CanvasItem now store children in LocalVector instead of Vector; Spatial::_is_vi_visible() and the vi_visible flag were removed. C++ that reaches into children directly (not via get_children()) or calls _is_vi_visible() breaks. The fork's navigation code iterates via public APIs; confirm no direct children access remains.
MEDIUM Dependency mbedTLS 2.28 → 3.6.7 is a major crypto-library API break (PSA crypto, config changes), though bundled and re-glued internally. SSL/TLS and crypto behavior changes; entropy now sourced from Godot's OS. Only matters if the fork (or a module) calls modules/mbedtls directly — Steamworks does its own networking, so GodotSteam is unaffected. None expected, but be aware if any custom code touches the mbedTLS API.
MEDIUM Physics Interpolation (behavior) 3D interpolation was rewritten into SceneTree ("same user API", but a complete rework). For games with physics/common/physics_interpolation enabled, visuals and edge-cases can change; new editor warnings flag non-interpolated physics bodies; ARVR nodes now default to interpolation off. Playtest if the project uses physics interpolation. Verify the fork's navigation/Steam interplay (which is physics-adjacent) still looks right.
MEDIUM Audio (behavior) New AudioServer mute feature. Editor now defaults to the Dummy driver when there is no audio output (CPU reduction). Adds project/editor settings; muting is disallowed on Android. Mostly an editor/runtime optimization, not a gameplay break. None for the game; just be aware editor audio may be muted until an output exists.
MEDIUM UI behavior Range::set_value revert restores signal emission even when the value is unchanged (undoing the "no emit on unchanged" optimization). Subtle: UI code that relied on the newer behavior may see extra value_changed signals. Low risk; note if any UI depends on the suppress-on-unchanged behavior.
LOW C# / Mono MonoGCHandle moved into the gdmono namespace to avoid conflicts with mono 6.14. Only relevant to C#/Mono builds. Ignore if the fork is GDScript/C++ only.
LOW Platform floors iOS min 15.0 and 32-bit removed; Android min SDK 21 and API 35 UI adjustments; new opt-in nonexclusive fullscreen on Windows. Only if shipping to those platforms with older targets.

Good news: the fork's navigation and CSG/triangle changes touch files upstream never modified in this range, and its LocalVector/PoolVector usage is already compatible with the new container API. The only genuine merge-conflict hotspots are spatial_editor_gizmos.cpp (minor) and the CI action/workflow files.

6. Recommendations

  1. Merge, then compile before reviewing behavior. The single highest-value check is a clean scons build of the merged tree (especially the GodotSteam module and navigation code) under the C++17 toolchain.
  2. Resolve the CI workflow merge manually — preserve the fork's debug_symbols input while adopting upstream's .scons_cache/ path and new cache actions.
  3. Verify the toolchain floor across CI images and dev machines (GCC ≥ 9 / Clang ≥ 6 / MSVC ≥ 2017 15.9). This is enforced at configure time and is the only "build will not start" risk.
  4. Playtest physics interpolation if the project enables it — the 3D interpolation rework is the largest behavioral change and its bugs would surface as visual jitter/teleporting, not crashes.
  5. Re-test the original "crash al seleccionar nodos" fix. The MSVC workarounds (#pragma optimize, volatile, evil print) may interact with the new compiler flags; confirm the crash stays fixed.
  6. Take the security wins. The mbedTLS 3.6.7, libpng 1.6.58, libwebm CVE-2019-2126 and CA-cert updates are pure upgrades — no reason to defer them.
